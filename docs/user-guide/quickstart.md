# 快速入门

本章节将帮助您在 5 分钟内开始使用 ComAssistant。

## 第一步：启动程序

双击桌面上的 ComAssistant 图标，或从开始菜单中启动程序。

## 第二步：建立连接

工具栏左上角的 **类型** 用于切换通信工作台：串口、TCP客户端、TCP服务器、UDP 和 HID 会显示不同的专用界面。右上角的 **模式** 只用于串口工作台的数据展示方式；切换到 TCP、UDP 或 HID 后，主体区域会变成对应的通信调试界面。

界面主题会同时作用于主窗口、工具窗口、弹出对话框、右键菜单和消息提示框。浅色主题偏冷白和专业蓝，暗色主题沿用原有 Apple 深色背景；默认操作、危险操作和禁用状态会使用不同视觉样式，便于在设置、导出、文件传输和绘图配置等弹窗中快速判断操作风险。设置页、工具箱编码页和常见表单控件会预留稳定尺寸，紧凑窗口下可滚动查看内容，避免带单位的数值框、较长下拉文本或底部操作按钮被裁剪遮挡。

### 串口连接

1. **选择类型**: 在工具栏"类型"下拉框中选择"串口"
2. **选择串口**: 在端口下拉框中选择您的串口设备（如 COM3）
3. **设置波特率**: 选择合适的波特率（常用 115200）
4. **打开连接**: 点击"打开串口"按钮

连接成功后，状态栏会显示"已连接: COMx"。

### TCP 客户端

1. **选择类型**: 在工具栏"类型"下拉框中选择"TCP客户端"
2. **填写服务器**: 在 TCP 客户端工作台填写服务器 IP、端口和连接超时
3. **自动重连**: 需要断线重连时勾选"断开后自动重连"并设置重连间隔
4. **建立连接**: 点击工具栏"连接"按钮
5. **收发数据**: 在工作台底部发送区输入文本或 HEX，网络流收发日志会显示在中间区域
6. **日志工具**: 可使用"自动滚动"、"复制"和"清空"管理网络流日志

### TCP 服务器

1. **选择类型**: 在工具栏"类型"下拉框中选择"TCP服务器"
2. **设置监听**: 在 TCP 服务器工作台设置监听端口和最大连接数
3. **启动服务**: 点击工具栏"启动服务"按钮
4. **管理客户端**: 客户端连接后会出现在目标客户端列表
5. **断开客户端**: 选中客户端后可点击"断开选中"主动关闭该连接
6. **发送数据**: 可选择"发送到客户端"或"广播"发送给所有客户端

### UDP

1. **选择类型**: 在工具栏"类型"下拉框中选择"UDP"
2. **设置端点**: 在 UDP 工作台设置本地端口、目标 IP 和目标端口
3. **绑定端口**: 点击工具栏"绑定端口"按钮
4. **选择远端**: 收到数据报后，发送方会加入"最近远端"列表，可一键切换目标
5. **清理远端**: 最近远端列表可通过"清空最近"重置
6. **发送数据报**: 输入文本或 HEX 后点击"发送数据报"，需要广播时勾选"广播发送"

### HID 连接

1. **选择类型**: 在工具栏"类型"下拉框中选择"HID"
2. **刷新设备**: 点击刷新按钮扫描当前系统可见的 HID 设备
3. **选择设备**: 在设备下拉框中选择目标设备，列表会显示 VID、PID 与接口号
4. **设置 Report**: 在 HID Report 工作台确认 Input、Output、Feature 长度和 Report ID
5. **打开连接**: 点击"打开 HID"按钮
6. **调试 Report**: 使用 Output payload 发送输出报告，使用 Set Feature/Get Feature 调试 Feature Report
7. **查看预览**: Output/Feature 输入变化时会显示完整 Report 预览；payload 超过可用长度时会显示截断提示

HID 模式不使用波特率；如果下拉框显示"HID 后端未启用"，说明当前本地构建没有找到 hidapi，需要使用发布构建或通过 vcpkg/toolchain 重新配置构建。HID 不是普通文本流，Report 长度、Report ID 和设备协议必须与厂商文档一致。

HID 打开后，Input 轮询、Output 写入和 Feature Report 操作会进入后台 worker 线程，并按同一设备句柄串行执行。关闭 HID 时程序会先释放 worker 中的设备句柄，避免 Feature 读写过程中直接关闭造成界面卡住或设备句柄残留。

## 第三步：发送数据

### 串口/TCP/UDP 文本发送
1. 在底部发送区输入文本
2. TCP/UDP 工作台可勾选"追加换行"自动在文本末尾加入 `\n`
3. 点击发送按钮；TCP/UDP 工作台也可在发送输入框按 `Ctrl+Enter` 快速发送

### 串口/TCP/UDP HEX 发送
1. 勾选"HEX发送"选项
2. 输入十六进制数据（如 `AA BB CC DD`）
3. 可点击"HEX格式化"把 `0x0a bb c` 规范化为 `0A BB 0C`
4. 点击发送按钮；TCP/UDP 工作台也可按 `Ctrl+Enter`

### HID Report 发送
1. 在 HID Report 工作台填写 Output payload 或 Feature payload
2. Output Report 会按 Output Report ID、Output 长度和"首字节为长度"选项构造
3. Feature Report 使用独立的 Feature Report ID 和 Feature 长度
4. Output/Feature 区域会显示 Report 预览、payload 字节数和截断提示
5. 可点击"HEX格式化"规范化 payload，报告历史会记录方向、类型、长度、HEX 和文本摘要

## 文件传输

工具栏的 **发送文件** 会打开文件传输中心，支持裸流分块、XMODEM/YMODEM/YMODEM-G 和自定义 OTA。

| 模式 | 适用场景 | 可靠性行为 |
|------|----------|------------|
| 裸流分块 | 下位机按顺序接收原始字节流 | 按块读取文件，等待本地发送队列确认后再读取下一块 |
| 自定义 OTA | 自定义 Bootloader 固件升级 | Header/Data/DONE 流式发送，可选 ACK、超时和重试；Magic 支持 4 字节 ASCII 或 `0x12345678UL` 形式的 `uint32_t`，发包时按小端写入前 4 字节 |
| XMODEM/YMODEM | 标准 Bootloader 或终端工具 | 按协议块读取文件，只缓存当前待 ACK 包；`NAK` 或超时重发当前包，完成/取消/失败释放文件句柄 |
| YMODEM-G | 硬件流控或低误码链路上的高速 YMODEM 变体 | 使用 `G` 握手；数据包不逐包 ACK，但仍逐包读取文件；接收端发现校验或序号错误会 `CAN` 中止 |

传输过程中状态会区分“传输中”“已暂停”“正在取消”“传输完成”“已取消”和“传输失败”。失败时会保留本地发送队列、连接断开、ACK 超时或协议重试等错误原因，便于重新连接或调整块大小后再试。

XMODEM 接收会在数据包校验通过后立即写入保存文件，只保留当前半包接收缓存，不再把整个接收文件常驻内存。标准 XMODEM 不携带真实文件大小，最后一包的 `CPMEOF` 填充会按协议块原样保存；需要精确文件长度时建议使用 YMODEM 或自定义 OTA。YMODEM-G 接收使用 `G` 握手，不对成功数据包逐包 ACK，适合低误码链路；如果检测到校验或序号错误，会发送 `CAN` 并失败退出。

## 第四步：接收数据

串口接收到的数据会自动显示在接收区：

- **文本标签页**: 显示 ASCII 文本
- **十六进制标签页**: 显示 HEX 格式
- **过滤标签页**: 根据关键词过滤显示
- **右键菜单**: 在文本、十六进制或过滤结果区域右键，可复制、全选、清屏、暂停/继续显示，并快速切换自动滚动、HEX 显示、时间戳和高亮。暂停显示不会丢弃接收数据，点击继续后会补刷暂停期间收到的内容
- **数据分窗**: 可通过工具菜单配置关键字或正则规则，把匹配数据路由到独立窗口。分窗会按行数和字符数保留最近内容，无换行长流超过上限时删除最早文本并保留最新文本，导出时只导出当前保留内容
- **数据表格**: 工具菜单中的数据表格用于结构化追踪 RX/TX 记录；点击清空会释放已显示记录、待刷新记录和表格缓存容量，后续新记录从 1 重新计数

TCP客户端、TCP服务器、UDP 和 HID 会在各自工作台显示专用收发日志。网络工作台日志支持自动滚动、复制和清空；HID 输入报告会按"接收时移除输入 Report ID"选项归一化后进入历史。

### 接收协议

可通过 **工具 → 接收协议** 选择当前接收解析器。`Raw` 会直接显示原始数据；`Lua Script` 会按稳定协议 ID `lua.script` 创建脚本解析器，并在后续接收数据时调用 `process(data, context)`。

选择 `Lua Script` 后，可打开 **工具 → 协议配置...**，在 `scriptSource` 多行编辑器里编写 Lua 脚本。字段校验错误会显示在对应字段下方；点击确定后，配置会随会话保存并可在下次加载时恢复。运行时解析错误会显示在状态栏，并可通过 **工具 → 协议诊断...** 查看最近错误、沙箱边界和当前配置 JSON。

旧版 **绘图协议** 菜单仍只用于 TEXT、STAMP、CSV、JustFloat 等绘图数据路由；它不会显示 Lua 脚本协议。

### 接收选项
- **时间戳**: 显示接收时间
- **自动滚动**: 自动滚动到最新数据
- **HEX显示**: 切换十六进制显示

## 第五步：保存数据

### 导出数据
1. 点击菜单 **文件 → 导出数据**
2. 在“数据导出”对话框选择格式（TXT、CSV、HTML、JSON，也支持 XML、二进制和十六进制转储）
3. 按需勾选时间戳、方向、来源、行号、HEX 显示，或按方向、时间、内容正则过滤
4. 选择保存位置并点击 **导出**

主窗口导出使用最近的结构化收发历史，覆盖串口、TCP、UDP 和 HID 的 RX/TX 数据；历史有记录数和字节数上限，清空当前数据时会同步释放导出历史，避免长时间运行后导出缓存无限增长。

串口和 TCP 的接收导出会按完整文本行合并底层分片；例如一条以换行结束的设备日志即使被驱动拆成多次接收，导出时仍是一条 RX 记录。UDP 和 HID 保持按数据报或 Report 粒度记录。

保存到文件时，导出器会按匹配记录流式写入 TXT、CSV、HTML、JSON、XML、二进制或十六进制转储，不再先复制全部过滤结果或拼接完整导出内容；预览仍只显示前几条记录，便于确认格式和过滤条件。

### 保存会话
1. 点击菜单 **文件 → 保存会话**
2. 选择保存位置
3. 下次可通过 **文件 → 加载会话** 恢复

## 快捷键

| 快捷键 | 功能 |
|--------|------|
| Ctrl+O | 打开/关闭当前连接 |
| Ctrl+L | 清空接收区 |
| Ctrl+E | 导出数据 |
| Ctrl+Enter | 在 TCP/UDP 发送输入框中快速发送 |
| F1 | 打开帮助 |
