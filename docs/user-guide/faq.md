# 常见问题 (FAQ)

## 连接问题

### Q: 串口打不开，提示"设备正在使用中"？

**A**: 可能的原因和解决方案：
1. 其他程序正在使用该串口 → 关闭其他串口工具
2. 串口设备未正确连接 → 检查 USB 连接
3. 驱动程序问题 → 重新安装驱动

### Q: 找不到串口设备？

**A**:
1. 确认设备已正确连接
2. 检查设备管理器中是否有 COM 端口
3. 点击"刷新"按钮重新扫描
4. 尝试重新插拔设备

### Q: 找不到 HID 设备或提示"HID 后端未启用"？

**A**:
1. 确认工具栏"类型"已切换为 HID，并点击刷新按钮重新扫描
2. 确认目标设备未被其他程序独占打开
3. 如果提示"HID 后端未启用"，说明当前构建未链接 hidapi；请使用发布构建，或通过 vcpkg/toolchain 安装 `hidapi` 后重新配置构建
4. 部分系统设备或安全设备可能不允许普通应用直接访问，需要使用厂商开放的 HID 接口或调整驱动/权限

### Q: 为什么切换到 TCP/UDP/HID 后，右上角"模式"不见了？

**A**: 右上角"模式"是串口工作台的数据展示模式，只控制串口的文本、终端、帧和调试显示。TCP客户端、TCP服务器、UDP 和 HID 现在都有自己的通信工作台，主体区域会切换为对应的网络或 HID Report 调试界面，因此不再显示串口模式选择。

### Q: 连接后无法收发数据？

**A**:
1. 确认波特率设置正确
2. 检查数据位、停止位、校验位设置
3. 确认设备端程序正常运行
4. 尝试交换 TX/RX 线（如果是手工连接）
5. HID 设备请确认输入/输出报告长度、Report ID 与设备协议一致

### Q: HID Output Report 和 Feature Report 有什么区别？

**A**:
1. Output Report 通过 HID 输出通道发送，适合普通输出报告
2. Feature Report 通过控制传输 Set/Get Feature 访问，常用于设备配置、状态查询或厂商自定义控制
3. 两者可能使用不同的 Report ID 和报告长度，请按设备描述符或厂商协议填写
4. 如果设备无响应，先确认 Report ID 是否需要为 0，以及长度是否包含 Report ID 字节

### Q: HID Report 预览显示"会截断"是什么意思？

**A**:
1. HID Report 的总长度包含 Report ID 字节，Output 勾选"首字节为长度"时还会额外占用 1 字节
2. 当 payload 超过剩余可用长度时，构造完整 Report 时会按固定长度截断
3. 看到截断提示时，应减少 payload、调大对应 Report 长度，或确认设备协议是否要求分包发送
4. 发送前可先查看 Report 预览，确认 Report ID、补零和最终 HEX 是否符合设备文档

### Q: TCP/UDP 工作台里的 HEX格式化、Ctrl+Enter 和自动滚动怎么用？

**A**:
1. "HEX格式化"会清理 `0x` 前缀和分隔符，并按字节输出大写 HEX，例如 `0x0a bb c` 会变成 `0A BB 0C`
2. 格式化后工作台会进入 HEX 发送模式，若要发送普通文本，请取消勾选"HEX发送"
3. 焦点在 TCP/UDP 发送输入框时，按 `Ctrl+Enter` 可快速发送当前内容
4. 关闭"自动滚动"后，新日志仍会追加，但视图会保留在当前历史位置，方便对照旧数据
5. UDP 的"最近远端"用于快速切换回最近收到数据报的发送方，可通过"清空最近"重置列表

## 数据问题

### Q: 接收到的数据是乱码？

**A**:
1. 波特率不匹配 → 调整为正确的波特率
2. 编码问题 → 尝试切换 ASCII/HEX 显示
3. 数据位设置错误 → 检查数据位设置（通常为 8 位）

### Q: 发送的数据设备收不到？

**A**:
1. 检查流控制设置
2. 确认硬件连接正确
3. 检查设备端接收程序

### Q: 数据显示不完整？

**A**:
1. 缓冲区溢出 → 降低发送频率
2. 显示刷新不及时 → 关闭时间戳显示
3. 数据量过大 → 清空接收区后重试

## 绘图问题

### Q: 绘图窗口不显示曲线？

**A**:
1. 确认选择了正确的绘图协议
2. 检查数据格式是否符合协议要求
3. 查看接收区是否有数据

### Q: 绘图卡顿？

**A**:
1. 减少数据点数量
2. 降低发送频率
3. 关闭其他绘图窗口
4. 启用 OpenGL 加速

### Q: 曲线数据异常？

**A**:
1. 检查数据格式是否正确
2. 确认数值范围合理
3. 查看是否有数据解析错误

## 性能问题

### Q: 程序启动慢？

**A**:
1. 清理日志文件
2. 减少快捷发送条目
3. 关闭不需要的功能

### Q: 内存占用高？

**A**:
1. 定期清空接收区
2. 减少绘图窗口数量
3. 限制数据缓存大小

### Q: CPU 占用高？

**A**:
1. 降低数据刷新频率
2. 关闭实时高亮
3. 减少同时打开的窗口

## 界面问题

### Q: 界面显示模糊？

**A**:
1. 检查 Windows 缩放设置
2. 右键程序 → 属性 → 兼容性 → 更改高 DPI 设置

### Q: 语言切换后部分文字未更新？

**A**:
1. 重启程序
2. 检查翻译文件是否完整

### Q: 主题切换不生效？

**A**:
1. 确认主题文件存在
2. 重启程序

## 脚本问题

### Q: Lua 脚本无法运行？

**A**:
1. 检查语法错误
2. 查看输出窗口的错误信息
3. 如果用于接收解析，确认已通过 **工具 → 接收协议 → Lua Script** 选择 `lua.script`
4. 在 **工具 → 协议配置...** 中确认 `scriptSource`、`entryFunction`、超时和内存限制配置正确
5. 通过 **工具 → 协议诊断...** 查看最近错误、当前配置校验和沙箱边界
6. 确认 API 调用正确；`serial.receive(timeout)`、外部 `scriptPath` 加载和脚本化构帧当前仍未开放

### Q: 脚本执行超时？

**A**:
1. 检查是否有死循环
2. 优化脚本逻辑
3. 增加超时时间

## 其他问题

### Q: 如何导出所有配置？

**A**:
1. 备份 `%APPDATA%\ComAssistant\config.ini`
2. 备份 `%APPDATA%\ComAssistant\quicksend.json`

### Q: 如何重置所有设置？

**A**:
1. 关闭程序
2. 删除 `%APPDATA%\ComAssistant\config.ini`
3. 重新启动程序

### Q: 如何报告 Bug？

**A**:
1. 收集日志文件：`%APPDATA%\ComAssistant\logs\`
2. 描述复现步骤
3. 提交到 GitHub Issues
