2. 文件传输 File Transfer

中文：工具栏 发送文件 按钮会打开统一文件发送中心，支持裸流分块、XMODEM/YMODEM/YMODEM-G 和自定义 OTA 三种路径。

English: The toolbar Send File button opens a unified file transfer center with raw chunks, XMODEM/YMODEM/YMODEM-G and custom OTA modes.

支持的协议 / Supported Protocols

模式 / Mode 数据块大小 / Block Size 特点 / Features
裸流分块 / Raw Chunks 1-4096 字节可配置 不增加协议头，按文件原始内容分块发送；第一版仅支持发送 / Sends original file bytes in chunks without protocol headers; send-only in this version
XMODEM 128 字节 基础校验和；发送时按块读取文件，只缓存当前待 ACK 包 / Basic checksum; send path reads the file block by block and keeps only the current packet for ACK retry
XMODEM-CRC 128 字节 CRC-16 校验；NAK 或超时重发当前包，EOT 阶段只重发 EOT / CRC-16 checksum; NAK or timeout retransmits the current packet, and EOT timeout retransmits EOT only
XMODEM-1K 1024 字节 大数据块传输；按 1K 块读取源文件 / Large block transfer; reads source files in 1K blocks
YMODEM 1024 字节 支持文件名和批量传输；发送头包只读取文件元数据，数据包按 1K 块读取，当前包 ACK 后重置重试计数 / Filename and batch support; the header uses metadata only, data packets read 1K chunks, and retry count resets after each packet ACK
YMODEM-G 1024 字节 适合硬件流控或低误码链路；使用 G 握手，数据包不逐包 ACK，发送端仍逐包读取文件，接收端发现错误会 CAN 中止 / For hardware-flow-control or low-error links; uses the G handshake without per-packet ACK, still reads the file packet by packet, and aborts with CAN on receive errors
自定义 OTA / Custom OTA 1-4096 字节可配置 发送文件头、数据块和结束包，可选 ACK、超时与重试；Magic 支持 4 字节 ASCII 或 0x12345678UL 形式的 uint32_t，按小端写入；第一版仅支持发送 / Sends header, data blocks and end packet with optional ACK, timeout and retry; Magic accepts 4-byte ASCII or uint32_t values such as 0x12345678UL and is written little-endian; send-only in this version

发送文件 / Send File

中文：XMODEM/YMODEM/YMODEM-G 标准协议发送已经完整改为按块读取文件，不再在启动或头包阶段一次性读取整个固件；普通 XMODEM/YMODEM 为保证重发可靠性只保留当前待 ACK 的协议包，NAK 或超时时重发当前包。YMODEM-G 不等待数据包 ACK，但仍通过事件循环逐包读取和发送，避免一次性堆积大文件协议包。完成、取消、失败或批量切换文件时会释放文件句柄。

English: XMODEM/YMODEM/YMODEM-G sending now reads files block by block instead of loading the whole firmware at start or header time. Standard XMODEM/YMODEM keep only the current packet waiting for ACK and retransmit it on NAK or timeout. YMODEM-G skips per-packet ACK but still reads and sends one packet at a time through the event loop to avoid accumulating large-file packets. File handles are released on completion, cancellation, failure, or batch file switches.

  1. 点击工具栏"发送文件" / Click the toolbar "Send File" button
  2. 选择裸流分块、XMODEM/YMODEM 或自定义 OTA / Select Raw Chunks, XMODEM/YMODEM or Custom OTA
  3. 按模式设置块大小、包间隔、ACK 或标准协议 / Configure block size, interval, ACK or standard protocol by mode
  4. 点击"浏览"选择文件 / Click "Browse" to select file
  5. 确认文件大小、CRC32、分块数和预计耗时 / Confirm file size, CRC32, block count and estimated duration
  6. 点击"开始传输" / Click "Start Transfer"

接收文件 / Receive File

中文：接收模式当前用于 XMODEM/YMODEM/YMODEM-G 标准协议。XMODEM 接收会在包校验通过后立即写入目标文件，只保留半包接收缓存，不再把整个文件累积到内存；由于标准 XMODEM 包不携带真实文件大小，最后一包的 CPMEOF 填充保持原样写入。YMODEM 接收会发送 C 握手，解析对端 0 号文件头中的文件名和大小，按声明大小保存数据，处理双 EOT 收尾，并在空文件头表示批次结束后完成。YMODEM-G 接收会发送 G 握手，成功数据包不逐包 ACK，EOT 后发送 ACK+G 请求下一个文件头；校验或序号错误会发送 CAN 并失败退出。裸流分块和自定义 OTA 第一版不实现 PC 侧接收。

English: Receive mode currently applies to XMODEM/YMODEM/YMODEM-G standard protocols. XMODEM receive writes each verified packet directly to the target file and keeps only partial-packet receive buffering instead of accumulating the whole file in memory; because standard XMODEM packets do not carry the real file size, final-packet CPMEOF padding is preserved. YMODEM receive sends the C handshake, parses the peer block-0 filename and size, saves exactly the declared data size, handles the double-EOT ending, and completes after the empty end-of-batch header. YMODEM-G receive sends the G handshake, skips per-packet ACK for valid data, sends ACK+G after EOT to request the next file header, and aborts with CAN on checksum or sequence errors. Raw chunks and custom OTA are send-only in this version.

  1. 选择 XMODEM/YMODEM 模式 / Select XMODEM/YMODEM mode
  2. 选择"接收文件"模式 / Select "Receive File" mode
  3. 选择保存路径 / Select save location
  4. 点击"开始传输"等待数据 / Click "Start" and wait
安全说明 / Security: YMODEM 文件名来自对端设备，应用只接受单个安全文件名；包含目录分隔符、盘符或 .. 的文件名会被拒绝，避免写出用户选择的保存目录。
YMODEM filenames come from the peer device. The application accepts only safe single filenames; names containing path separators, drive prefixes or .. are rejected to keep writes inside the selected save location.

3. IAP固件升级 IAP Firmware Upgrade

中文：IAP 菜单当前复用文件传输中心的 IAP 模式，不再使用旧的独立 IAPUpgrader 模块。请按设备 Bootloader 支持的协议选择自定义 OTA、XMODEM、YMODEM、YMODEM-G 或裸流分块。

English: The IAP menu reuses the file transfer center's IAP mode and no longer uses the legacy standalone IAPUpgrader module. Choose custom OTA, XMODEM, YMODEM, YMODEM-G or raw chunks according to the device Bootloader.

操作步骤 / Steps

  1. 确保设备处于Bootloader模式 / Ensure device is in Bootloader mode
  2. 打开 工具 → IAP升级，或点击工具栏"发送文件"后选择设备支持的模式 / Open Tools → IAP Upgrade, or click toolbar "Send File" and select the mode supported by the device
  3. 选择固件文件（.hex 或 .bin）并确认大小、CRC32 和分块数 / Select firmware file and confirm size, CRC32 and block count
  4. 按 Bootloader 配置标准协议或 OTA ACK 参数 / Configure the standard protocol or OTA ACK options for the Bootloader
  5. 点击"开始传输" / Click "Start Transfer"
  6. 等待传输完成 / Wait for completion
⚠️ 警告 / Warning: 固件升级过程中请勿断开连接或关闭电源！
Do not disconnect or power off during firmware upgrade!

6. 数据分窗 Data Windows

中文：通过工具菜单配置数据分窗规则后，应用会按关键字或正则表达式把匹配数据路由到独立观察窗口。分窗用于辅助观察最近匹配内容，不替代完整日志保存。

English: Configure data-window rules from the Tools menu to route matching data into separate observation windows by keyword or regular expression. Data windows are for recent matched content and do not replace full log export.

中文：数据分窗同时按最大行数和字符数保留最近内容；如果设备持续输出无换行长流，超过上限后会裁剪最早文本并保留最新文本。分窗导出只保存当前保留内容。

English: Data windows keep recent content using both line and character limits. For long streams without line breaks, the oldest text is trimmed once the limit is exceeded while the newest text is retained. Export saves only the currently retained content.

7. 数据导出 Data Export

中文：通过 文件 -> 导出数据 打开增强导出对话框。主窗口会记录最近的结构化 RX/TX 历史，覆盖串口、TCP Client、TCP Server、UDP、HID Input/Output/Feature Report，可导出为多种格式。

English: Open the enhanced export dialog from File -> Export Data. The main window records recent structured RX/TX history for serial, TCP Client, TCP Server, UDP and HID Input/Output/Feature reports, then exports it in multiple formats.

中文：导出历史按记录数和 payload 字节数双上限保留最近数据；关闭导出对话框会销毁其中复制的记录和预览文本，清空当前数据时会同步释放导出历史，断开连接时会自动裁剪到最近 256KB/256 条。过滤统计使用与真实导出相同的方向、时间和内容正则规则。

English: Export history keeps recent data using both record-count and payload-byte limits. Closing the export dialog destroys copied records and preview text; clearing current data releases the export history; disconnecting trims it to the latest 256 KB/256 records. Filter statistics use the same direction, time and content-regex rules as the actual export.

中文：串口和 TCP 接收历史会按完整文本行合并底层分片，避免一条设备日志因为 readyRead 拆包被导出成多条；如果长时间没有换行，缓冲达到上限后会按当前片段提交，保证内存有界。UDP 和 HID 保持按数据报或 Report 粒度记录。

English: Serial and TCP receive history merges low-level chunks into complete text lines, preventing one device log from being exported as several readyRead fragments. If no line break arrives for a long stream, the bounded buffer is committed as a chunk. UDP and HID keep datagram/report granularity.

中文：保存到文件时，TXT、CSV、HTML、JSON、XML、二进制和十六进制转储都会按匹配记录流式写入目标文件；导出器只提前统计数量和字节数，不会先复制全部过滤结果或拼接完整导出内容。

English: File export streams matching records directly to TXT, CSV, HTML, JSON, XML, binary and hex dump targets. The exporter pre-counts records and bytes only, without copying all filtered records or assembling the entire output in memory first.

格式 / Format 扩展名 用途 / Usage
